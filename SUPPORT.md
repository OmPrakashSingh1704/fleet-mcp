# Support

## Asking a question

- **Usage questions, ideas, "how do I..."** — open a
  [GitHub Discussion](../../discussions) if enabled for this repository, or
  a regular issue using the "Question" option if Discussions isn't enabled
  yet.
- **Something is broken** — open a [bug report](../../issues/new?template=bug_report.yml).
  Please include your Python version, the command you ran, and the full
  output — see the template for the full checklist.
- **You want a new feature or a new fleet capability** — open a
  [feature request](../../issues/new?template=feature_request.yml).
- **You want support for a new LLM provider/model** — open a
  [new model support request](../../issues/new?template=new_model_support.yml).
  Note that `model-adapters-mcp` is not built yet (see the
  [README roadmap](README.md#status--roadmap)); these requests are tracked
  for when that lands.
- **You found a security problem** — do **not** open a public issue. See
  [SECURITY.md](SECURITY.md) and use GitHub's private security advisory
  flow instead.

## What to expect

This is an open-source project maintained on a best-effort basis. There's no
SLA on issue responses outside of the security response targets in
[SECURITY.md](SECURITY.md). Well-scoped bug reports with a reproduction and
well-scoped feature requests that explain the use case get triaged fastest.

## Contributing a fix yourself

If you'd rather fix something than wait for it, see
[CONTRIBUTING.md](CONTRIBUTING.md) for dev setup and the PR process.
